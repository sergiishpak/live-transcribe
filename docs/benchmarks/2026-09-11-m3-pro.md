# M3 Pro live-transcription check — 2026-09-11

Machine: M3 Pro, 18 GB unified memory, macOS 26.6.2.

The final build uses the local `Parakeet Unified 0.6B` CoreML streaming model
with its 320 ms `[70,2,2]` context. Its one-time cache download was 594 MB.

## Controlled system-audio check

Input, played through macOS `say` as system audio:

> Hello. This is a live transcription test for English system audio. The quick brown fox jumps over thirteen lazy dogs.

Observed live text:

> Hello, this is a live transcription test for English system audio, the quick brown fox jumps over 13 lazy dogs

During a second, longer `say` playback, text was visible while audio was still
playing; the first manual screen check at about 1.6 seconds already showed the
opening sentence. This confirms live rather than end-of-recording output. It
does not establish a precise latency distribution for real calls.

## Model choice

`Parakeet EOU 120M` at both 160 ms and 320 ms produced unstable output in the
same controlled sentence. `Parakeet TDT 0.6B v2` is cached locally and has
strong batch accuracy, but FluidAudio's sliding-window wrapper needs about 13
seconds before its first normal window, which is unsuitable for this app.

The Unified 0.6B 320 ms stream was kept because it was the first candidate to
produce a complete, accurate controlled transcript while speech was ongoing.
